Why Kraken wins: transfer > from-scratch

Kraken fine-tunes from reichenau_lat — a strong, ſ-faithful Latin base of roughly millions of characters — so 264 Douay-Rheims lines only need to refine it (resize='union' extended the codec 223→233, adding 10 DR-only glyphs while keeping the base's learned strokes). Calamari, pinned to v1.0.7 with no compatible ſ-faithful warm-start base, learns entirely from 264 lines — it plateaus at 83.9% validation while its training error keeps falling to 0.12: textbook small-data overfitting. Both engines are surface-honest — Calamari did learn ſ, †, and archaic spelling — Kraken is simply more accurate.

Both trainers were broken; both were fixed

The two-track mandate earned its keep: each engine had a blocker that would have silently sunk a single-track attempt.

Track 1 · Kraken 7.0.2

"No training data" was a lie

The ketos train CLI reported an empty dataset from provably-valid data. Root cause: the datamodule passes im_transforms=None; on raw-bbox data .add() then sets self.transforms.valid_norm → AttributeError — swallowed by a broad except into an empty set. A silent-degradation trap; DEBUG logging exposed it.

Fix → Python-API trainer overriding one method to pass a real transform. Best val 0.9396.

Track 2 · Calamari 1.0.7

A 2020 engine on a 2026 stack

pip on Python 3.12 resolves only calamari 1.0.7 (2.x needs an old TensorFlow). It runs against modern TF only with two env vars on every call: TF_USE_LEGACY_KERAS=1 (Keras-3 rejects its symbolic K.cast) and PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python (protobuf 4+ guard).

Fix → isolated venv + both env vars. Trains from scratch to 83.9% val.

What held the line

  • Consensus stayed out of the ladder — each source's OCR is improved singly, honestly.
  • Grain-correct metric (page + ~20-word window), never the per-verse metric that deflates prose.
  • ſ surface-safe throughout — NFC (never NFKC), no dictionary or language model, and the ſ-count companion check ran on every output because edit_ratio is ſ-blind.
  • Base = reichenau_lat (ſ-faithful); catmus-print-large (which modernises ſ→s) was rejected.
